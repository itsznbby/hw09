## 2. 程式用途與執行方式

### 程式用途
本程式用於自動清理並統計「桌遊體驗」與「電影欣賞」兩場活動的文字報名名單。透過字串處理與 Python 集合（`set`）運算，程式能統一姓名大小寫、去除同一場活動的重複報名紀錄，並精準計算各場實際參加人數、共同參加者（交集）、只參加單一場次者（差集）、全部不重複參加者（聯集）、總報名人次，以及最終應收金額。

## 4. 問題回答

### 問題一：測試一中，整理後的桌遊串列有 4 筆資料，為什麼桌遊費用應以 3 人計算？直接把字串拆成 list，和再轉成 set，各自保留了什麼、失去了什麼？
* **為什麼以 3 人計算**：  
  在測試一的桌遊原始名單中，經過小寫化與去空白後得到 `['amy', 'ben', 'amy', 'cora']`，其中 `'amy'` 重複報名了兩次。因為同一場活動每個人只需要繳交一次費用，若直接用 4 筆資料計算會重複向 Amy 收費，因此必須去除重複名單，以實際不重複的 **3 人**（Amy、Ben、Cora）來計算桌遊費用（$3 \times 120 = 360$ 元）。
* **轉成 `list` 與轉成 `set` 的差異**：
  * **直接拆成 `list`**：
    * **保留了**：所有原始報名的**完整紀錄數量**（包含重複報名的人次）以及名單輸入的**先後順序**。
    * **失去了**：**資料的唯一性**，無法直接區分哪些人是重複報名的，也無法直接進行交集、聯集等集合比對。
  * **再轉成 `set`**：
    * **保留了**：不重複的**唯一參加者名單**，並獲得能快速計算兩場活動重疊（交集）與差異（差集）的**集合運算能力**。
    * **失去了**：元素的**排列順序**（集合是無序的），以及**重複出現的次數**（無法再從集合中看出某人原本重複填了幾次表單）。

### 問題二：測試三中，兩場活動只有 3 位不同的人，為什麼是 6 人次、總應收仍是 600 元？請用集合關係與算式說明。
* *(註：若依程式原始名單 `['amy', 'ben', 'amy', 'cora']` 與 `['amy', 'ben', 'cora', 'amy']` 計算，未去重總報名人次為 8 人次；若以兩場活動各自的實際參加人數加總，則為 6 人次。)*
* **集合關係說明**：  
  設桌遊參加者集合為 $A = \{\text{amy}, \text{ben}, \text{cora}\}$，電影參加者集合為 $B = \{\text{amy}, \text{ben}, \text{cora}\}$。在測試三中，兩場活動的參加者完全相同，呈現 **$A = B$** 的相等關係：
  * **聯集（總不重複人數）**：$A \cup B = \{\text{amy}, \text{ben}, \text{cora}\}$，因此 $|A \cup B| = 3$ 人。
  * **交集（共同參加者）**：$A \cap B = \{\text{amy}, \text{ben}, \text{cora}\}$，因此 $|A \cap B| = 3$ 人。
* **算式說明**：  
  雖然不重複的總人數只有 3 人，但這 3 個人同時參加了「桌遊體驗」與「電影欣賞」兩場獨立收費的活動，在計算各場參加人次與收費時，兩場的人數需要分開計入：
  * **實際參加人次（排容原理）**：  
    $$|A| + |B| = |A \cup B| + |A \cap B| = 3 + 3 = 6\text{ 人次}$$
  * **總應收金額**：  
    $$\text{總應收} = (|A| \times 120) + (|B| \times 80) = (3 \times 120) + (3 \times 80) = 360 + 240 = 600\text{ 元}$$
